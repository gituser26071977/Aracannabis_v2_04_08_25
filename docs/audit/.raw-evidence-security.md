# Raw Evidence — Security/RBAC (Agent 6)

## 2 camadas parcialmente sobrepostas
1. **Aplicação Flask/SIAP ativa** com flask-jwt-extended + routes/auth.py + tenant_middleware + models.py legado
2. **Plataforma AraOS** com módulos próprios (identity/tokens.py, permissions.py, tenant/middleware.py, audit/ledger.py)

## Login
- **Profissional**: routes/auth.py:82 POST /login, email ou usuario, PBKDF2-SHA256 100k iter, 12h access token (apenas access, NÃO refresh, NÃO tenant_id)
- **Paciente**: routes/patient_auth.py:149 POST /login, email, token com `user_type:patient`, 12h access
- **Legado/paralelo**: auth.py (não usado pelo app principal)
- **Provider AraOS**: araos/platform/identity/tokens.py — access (HS256) + refresh (30d, usage-unique) + jti revocation em memória

## JWT
- **Algoritmo provider AraOS**: HS256 (não RS256)
- **Claims Flask**: sub, exp (12h), iat, user_type (paciente). SEM tenant_id, SEM roles, SEM permissions
- **Claims AraOS provider**: sub, tenant_id, org_id, clinic_ids, roles, permissions, actor_type, jti, iat, exp, type, version, email, full_name, plan, delegated_by
- **Secret**: JWT_SECRET_KEY (env, mínimo 32 chars; aborta em prod se fraco). MAS docker-compose.siap.yml tem `SECRET_KEY=SIAP_SECRET_REDACTED` (hardcoded, < 32 chars)
- **Refresh**: provider AraOS usa set em memória (`_revoked_jtis: set = set()  # Em produção: Redis/DB`); Flask NÃO emite refresh
- **MFA**: APENAS modelo + evento (mfa_enabled, MFA_ENABLED), SEM TOTP/OTP/recovery codes

## RBAC
- **Permission registry**: araos/platform/identity/permissions.py — NÃO é Enum, é classe de constantes (Permission)
- **Total permissions**: 106
- **Roles**: 12 (admin, physician, secretary, manager, patient, agent, service_account, viewer, neuro_physician, health_secretary, scientific_producer, intelligence_curator)
- **Decorators**: @require_permission (auth_decorators.py), @require_staff_role, @require_roles, @require_tenant (tenant/middleware.py)
- **APLICAÇÃO REAL**: ZERO endpoints produção com @require_permission (só exemplos em docstrings). Endpoints usam só @jwt_required() + verificações manuais

## Tenant Isolation
- **3 mecanismos divergentes**:
  1. Middleware principal (tenant_middleware.py): tenant derivado EXCLUSIVO do vínculo do usuário autenticado
  2. Helpers de rotas Sprint 4 (_helpers.py): prioridade X-Association-ID > X-Tenant-ID > tenant_id na identity JWT
  3. Platform resolver: JWT/API key/service account/X-Tenant-ID
- **`tenant_required`**: NÃO existe com esse nome; existe @require_tenant no platform/middleware.py (não usado)
- **`_assert_same_tenant`**: existe em araos/clinical/knowledge/infrastructure/repository.py (PermissionError se mismatch)
- **Filtro SQLAlchemy automático**: tenant_lib.py via do_orm_execute + before_flush; bypass com execution_options(skip_tenant=True) ou g.is_superadmin; depende de g.current_association
- **Filtragem explícita**: presente em admin.py, pharmacy.py, followup.py, cannabis.py, twin.py, audit/ledger.py
- **Inconsistências**: middleware engole exceções; helpers aceitam header contradizendo middleware; login Flask não emite tenant_id

## Audit Log
- **AraOS central**: araos/platform/audit/ledger.py — append-only, hash chain SHA-256, tenant-scoped, AuditEntry com before/after, IP, UA, correlation ID
- **AuditService.log()**: existe mas SEM integração em rotas (sem @audit decorator)
- **LogAtividade legado**: models.py com campos simples (profissional_id, associacao_id, acao, detalhes, data_hora); gravações manuais em varios routes (pacientes, consultas, evolucoes, dosagens, lgpd, admin, ai_management)

## CSRF
- **Implementação**: security_config.py (custom, não Flask-WTF)
- **Token global**: app_cors_livre.py gera secrets.token_hex(32); endpoint público GET /api/csrf-token retorna token do processo
- **Validação**: hmac.compare_digest, ignora GET/HEAD/OPTIONS, exige ≥32 chars em prod
- **Aplicação**: ZERO endpoints produção com @csrf_protect; só em tests/security/test_p0_remediation_m18.py

## CORS
- Origins permitidas: localhost:3000-3010, localhost:5000/5002/5003/5010, backend:5002, visualsmartflow.com.br, araos.visualsmartflow.com.br, 192.168.0.104:3000/5002, 127.0.0.1:3000/5002
- 192.168.0.104:3000 duplicado
- X-Association-ID removido da allowlist
- SEM wildcard *
- supports_credentials=True

## Rate Limiting
- Flask-Limiter: 5000/h + 200/min default; 10/min login; 100/min sensíveis; moving-window; Redis opcional, fallback memory://
- Chave: JWT identity ou IP anônimo
- Aplicado em: registro, login, troca senha, recuperação, definição
- IA rate limit específico (require_ia_rate_limit)

## SQL injection
- ORM com filter_by + binds + .where
- Não localizado padrão amplo de interpolação direta
- Catalogação não substitui revisão linha-a-linha

## XSS / Headers
- sanitize_input remove `<>'";` (não é escape contextual HTML)
- CSP: nonce por request, object-src 'none', frame-ancestors 'none', upgrade-insecure-requests, mas style-src 'unsafe-inline'
- Headers: nosniff, DENY frame, XSS-Protection, HSTS, Referrer-Policy, Permissions-Policy
- Não confirmado add_security_headers registrado como after_request

## File Upload
- MAX_CONTENT_LENGTH = 16 MiB (handler 413 diz "50MB" — divergência)
- Extensões: txt, pdf, imagens, doc/docx
- secure_filename + allowlist
- SEM inspeção magic bytes, SEM MIME real, SEM AV/ClamAV, SEM sandbox

## Pontos críticos catalogados (sem prioridade atribuída)
1. RBAC não aplicado em endpoints
2. Tenant pode vir por header em várias rotas
3. Login Flask não emite tenant_id
4. Middleware engole exceções e perde contexto
5. Refresh token ausente no Flask login
6. MFA sem implementação operacional
7. CSRF não aplicado em produção
8. Endpoint /api/csrf-token expõe token do processo
9. Audit ledger central não integrado às rotas
10. Secret hardcoded em docker-compose.siap.yml
11. Uploads sem inspeção de conteúdo
12. Handler 413 com mensagem divergente do limite real
13. Revogação JWT provider AraOS só em memória
14. Implementações paralelas de auth/token com claims divergentes
